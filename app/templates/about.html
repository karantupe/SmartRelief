THE IDEA BEHIND THE PROJECT

Better decisions for critical relief supplies.

SmartRelief is an educational optimization project that explores how algorithmic decision-making can help plan drone payloads for disaster-response scenarios.

Try the optimizer →

01 · THE PROBLEM

Why is SmartRelief needed?

Limited carrying capacity

A drone cannot carry every available supply. The payload must stay within a maximum weight, so some items may need to be left behind.

Different supplies, different value

Medical kits, food packs, clean water and emergency equipment have different assigned values. A good selection maximizes total value without exceeding capacity.

Time and computing resources

Some algorithms can guarantee an optimal solution but may become expensive as the number of items grows. Others are fast but may miss the best combination.

Transparent decisions

SmartRelief makes the selected items, total weight, total value, and algorithm measurements visible so users can examine the result.

02 · MATHEMATICAL MODEL

The 0/1 Knapsack problem

Each available item has a weight and a value. Each item is either selected or not selected. Splitting an item is not allowed.

Objective: maximize the total value of selected items.

Constraint: the sum of selected weights cannot exceed the drone capacity.

Decision: for every item, choose either 1 (take it) or 0 (leave it).

Current scope: SmartRelief currently models one payload constraint: weight. Real deployments may also need volume, battery energy, flight range, urgency, delivery deadlines, and safety constraints.

03 · WHY COMPARE ALGORITHMS?

One problem. Four different strategies.

The comparison page runs the algorithms on the same input so their outputs and performance can be examined fairly.

ALGORITHM 01

Recursive Backtracking

Explores include-or-exclude choices recursively. It is useful for understanding exhaustive search and can find an optimal solution, but its worst-case runtime grows exponentially.

ALGORITHM 02

Dynamic Programming

Reuses solutions to overlapping subproblems. For the classic integer-capacity knapsack model, the standard implementation takes O(nW) time, where n is the number of items and W is capacity.

ALGORITHM 03

Greedy

Makes local choices, commonly based on value per unit weight. It is often fast, but for 0/1 knapsack it does not guarantee the optimal result.

ALGORITHM 04

Branch and Bound

Searches candidate solutions while pruning branches that cannot beat the best known solution. It can find an optimum with a valid bound, though worst-case runtime is exponential.

04 · MEASUREMENT

What do the comparisons tell us?

Solution value

How much total assigned relief value was selected?

Execution time

How long did the algorithm itself take to run in C++?

Feasibility

Did the selected items stay within the capacity limit?

Optimality gap

How far is a candidate solution below the chosen reference value? A zero gap means equal value to that reference; it proves optimality only if the reference is itself known to be optimal.

05 · POTENTIAL APPLICATIONS

Where could this idea be useful?

Disaster relief

Explore payload selection for medicine, food, water and emergency kits after floods, earthquakes or storms.

Medical delivery

Model how a limited payload might prioritize medical supplies for remote or hard-to-reach areas.

Remote communities

Study supply selection for locations with difficult road access or disrupted transport.

Emergency logistics

Use the same optimization concepts to examine limited vehicle space, relief kits or warehouse packing.

Algorithm education

Visualize how exact methods, dynamic programming and heuristics differ on reproducible inputs.

Future research

Extend the model with volume, battery, urgency, multiple trips or multi-drone coordination.

Important limitation: SmartRelief is a learning and simulation project, not a certified emergency dispatch system. Item values are modeled scores, not clinical priority assessments. Real relief operations require expert oversight, safety constraints and validated operational data.
